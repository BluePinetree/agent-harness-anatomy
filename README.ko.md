![license: MIT](https://img.shields.io/badge/license-MIT-blue)

> 별도로 아카이브돼 있습니다 — 코드와 전체 커밋 이력은 [SOURCE.md](SOURCE.md) 참조.
> 이 저장소에 있는 것은 분석입니다: 실제로 무엇이 일을 하고 있었는가, 무엇이 망가졌는가,
> 그리고 원래의 연구 질문이 왜 검증 불가능한 것으로 판명됐는가.

## 알아둘 만한 다섯 가지

1. **프레임워크는 멀티에이전트 조율을 한 적이 없습니다.** 코드 전체에서 프레임워크 실행
   호출이 전부 **에이전트 1개 + 작업 1개**였습니다. 조율은 직접 짠 오케스트레이터가 했습니다.
   `grep`으로 확인 가능하고, 이 사실이 연구의 독립변수 자체를 무효화했습니다.
   → [findings/01](findings/01-single-agent-wrapper.md)

2. **증거와 증언을 나누는 것이 가장 이식성 높은 아이디어입니다.** AI가 쓴 코드가 남긴 숫자는
   주장입니다. AI가 못 고치는 코드만 증거를 만듭니다. 아래 신뢰성 문제 전부가 이 선이
   없었던 데서 나왔습니다. → [findings/02](findings/02-evidence-vs-testimony.md)

3. **위험한 실패는 성공이라고 보고합니다.** 810회 탐색으로 설정됐는데 한 번도 실행되지 않고
   *"완전 검증"* 으로 기록된 사례. 목표 70%인데 68.86을 달성으로 판정한 사례. 학습 3회가
   조용히 1회로 줄어든 사례. **종료코드 0은 성공 신호가 아닙니다.**
   → [findings/03](findings/03-silent-success.md)

4. **실패한 실험도 전부 논문을 만들었습니다. 16건 중 16건.** 집필 단계는 실행 단계의 성공
   여부에 의존하지 않았습니다. → [findings/04](findings/04-papers-without-results.md)

5. **진짜 엔지니어링은 12시간 실행을 살려두는 쪽이었습니다.** 파이프 교착, GPU를 잡은 유령
   프로세스, 살아있는 실행을 죽이는 정리 작업, 시간 초과를 코드 버그로 오진해 3번 반복한 것.
   **짧은 과제 벤치마크에는 이런 게 나타나지 않습니다.**
   → [findings/05](findings/05-long-horizon.md)

## 시스템이 무엇이었나

연구 질문을 자연어로 받아 논문까지 만드는 파이프라인입니다.

```
질문 → 계획 → 설계 → 코드 → 실행 → 분석 → 집필
```

CrewAI 기반이고, 3사 비교를 위해 AutoGen·LangGraph를 부분 이식했습니다. 파이썬 약 14,500줄,
React 스트리밍 화면, 사람 승인 게이트 5개.

**돌아갔습니다.** 원래 집계로 실행 폴더 271개 — 이 숫자가 무엇을 말하고 무엇을 말하지 않는지는
위 재집계 주석 참조 — 결과 파일 96개, 논문까지 생성. 이 저장소가 답하는 질문은
*돌아갔는가*가 아니라 **그만큼 돌려서 무엇이 보였는가**입니다.

## 실제로 일을 하고 있던 것

흥미로운 발견은 프레임워크 계층에 대한 **부정적 결과**입니다.

| 계층 | 줄수 | 실제로 한 일 |
|---|---|---|
| 직접 짠 오케스트레이터 | 2,350 | **단계를 순서대로 실행. 이게 멀티에이전트 시스템이었다** |
| 단계별 로직 | 3,755 | 프롬프트 구성, 출력 파싱, 수리 루프 |
| 장기 실행 관리 | ~1,400 | 프로세스 감독, 생존 판정, 중단 복구 |
| 골격 생성기 | 1,018 | AI가 고치면 안 되는 코드를 생산 |
| **프레임워크** | — | **모델 호출을 7번 감쌌다** |

추론이 아니라 실측입니다. 프레임워크 실행 호출은 7곳이고, 7곳 전부
`Crew(agents=[task.agent], tasks=[task])` — 에이전트 1개, 작업 1개입니다. 순차 프로세스도,
계층 위임도, 에이전트 간 메시지도 없습니다. 가장 복잡한 코드 생성 단계는
**프레임워크를 아예 import 하지 않고** 모델을 직접 호출합니다.

**원래 연구에 미친 결과.** 세 프레임워크를 나머지 변수를 통일해 비교하는 설계였는데, 각
프레임워크의 고유 동작이 한 번도 호출되지 않으면 세 구현이 전부 *"모델을 정해진 순서대로 호출"*
로 수렴합니다 — **import 문만 다르고 프로그램은 같습니다.** 독립변수가 코드에 존재한 적이
없었습니다. 그래서 비교를 철회했고, 이것이 비교 결과보다 더 흥미로운 발견입니다.

## 증거와 증언

이 프로젝트에서 다른 어떤 에이전트 시스템으로든 가져갈 유일한 아이디어입니다.

| | 누가 쓰나 | 판정에 |
|---|---|---|
| **증언** | AI가 생성한 실험 코드 | ❌ 기록만. 판정 근거로 쓰지 않음 |
| **증거** | AI가 못 고치는 코드 | ✅ 유일한 판정 근거 |

**왜 이 선이 필요한가 — 보관된 실행 29건 실측** (위 재집계 주석에서 재현되지 않은 수치입니다.
재집계 기준으로는 44건):

| | |
|---|---|
| 실제로 받은 설정을 기록한 실행 | **1 / 29** |
| 검증 데이터 성능을 보고한 실행 | **0 / 29** |
| 학습 횟수를 알 수 있는 실행 | **3 / 29** |
| 스스로 성공이라 한 실행 | **20 / 29** |

그리고 결과 파일에 **규격이 없습니다.** AI가 생성한 코드가 쓰기 때문입니다. 29건에서
**가장 흔한 지표 이름조차 2번**만 나옵니다. `metrics` 자리에 `error`, `traceback`, `host`,
`cwd`가 들어있는 실행도 있습니다.

> **AI의 출력을 파싱해서 판정하는 방식은 원리적으로 신뢰할 수 없습니다** — 규격이 실행마다
> 새로 만들어지니까요.

해결은 통계가 아니라 구조입니다. 고정 코드가 이름 공간을 소유하고 별도 블록에 씁니다.
AI가 지은 이름은 증언에 남겨 무시합니다.

## 장기 실행

각 장치는 다중 시간대 실행이 **로그만 봐서는 알 수 없는 방식으로** 죽었기 때문에 존재합니다.

| 장치 | 계기가 된 실패 |
|---|---|
| stdout/stderr 별도 읽기 스레드 | 파이프 버퍼가 차서 교착. **오류도 출력도 없이** 멈춤 |
| 프로세스 트리 종료 | 부모만 죽이면 자식이 **GPU를 잡은 채** 남음 |
| 멈춤 감지 + 심장박동 | **21시간 무이벤트.** 실행 중인지 죽었는지 구분 불가 |
| 파일락 소유권 (살아있음/죽음/**모름**) | PID 검사는 거짓말을 함. Windows에선 PID 신호가 자기 콘솔을 때림 |
| 중단 복구 | 중단 한 번에 몇 시간 손실 |
| 출력 꼬리 제한 | 이벤트 하나가 **1.6GB**까지 커짐 |

**가장 뾰족한 건 장치가 아닙니다.** 90분 제한에 걸려 죽었는데, 분석 단계가 원인을
**정확히 진단**했습니다 — *"계획이 시간 예산에 비해 너무 크다."* 그리고 **똑같은 설정으로
3번 반복하고 4.5시간을 버렸습니다.** 예산을 바꿀 수단이 없었기 때문입니다.

능력 부족이 아닙니다. **에이전트는 답을 알았고 레버가 없었습니다.**

## 범위와 한계

독자가 찾아내기 전에 먼저 밝힙니다.

- **원래 집계로 실행 폴더 271개, 결과 파일 96개.** 2026-09-09 재집계로는 디렉토리 270개,
  그중 파일이 있는 것 224개이고, 96개는 정확히 재현됐습니다. 운영자 1명, 기계 1대, 모델 계열
  1개, 과제 3종
- **통제된 벤치마크가 아닙니다.** 디버깅하면서 조건이 바뀌었습니다. 병리 현상은 **존재
  증명**이지 발생률이 아닙니다
- **완주한 프레임워크는 1개**입니다. 나머지 둘은 부분 이식으로 끝났습니다
- **개선 루프는 세 과제 모두 꺼져 있었습니다.** 방법론을 탐색하지 않고, 지정된 것을 구현합니다
- **사전등록 시점.** [protocol/](protocol/)의 프로토콜은 **이 저장소의 첫 커밋 이후** 작업을
  다룹니다. 보관된 실행에는 적용되지 않습니다 — 그건 사후 분석입니다

### 작업 방식

무엇을 만들지, 무엇을 측정할지, 그 숫자가 무엇을 뜻하는지, 언제 멈출지 — **판단은 전부
제 것입니다.** 시스템과 이 기록의 구조도 제가 잡았습니다. **반복적인 코드와 뼈대 설계,
그리고 문장 작성의 상당 부분은 AI에 맡겼습니다.** 커밋에 공동 작성자 표기가 붙은 것은
그 때문입니다.
